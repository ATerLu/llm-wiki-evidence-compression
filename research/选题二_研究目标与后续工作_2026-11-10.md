## 2. 研究问题、载体与边界

**主实验系统定位，2026-11-12。** 采用固定候选的 RAG 问答链路，实验模块放在候选获取与阅读器之间。LLM-Wiki 提供离线证据编译与持久化出处，在线用于定位、核验和装配原文。现有产物是带原句和来源版本的关系索引。正式方法对照固定同一套低成本原文选证器，切换是否使用编译索引，保留 A 完整候选。端到端 Wiki 页面遍历、持续维护和 Agent 自修复可作为后续应用验证。[现有编译实现与边界](../topic2/reports/等预算人工出处诊断与Wiki编译说明_2026-11-11.md)

**Wiki 与编译方向的最近对照，2026-11-12。** Ming 等的 LLM-Wiki 已在 HotpotQA、MuSiQue 等任务上用带链接的 Wiki 与 Agent 搜索、阅读和循链做问答。WiCER 已用诊断探针发现并修复编译漏事实。Yu 等的《Context as Infrastructure》已检验主张与逐字原句的离线配对、证据充分性判断及原文回退，并在 200 道 FRAMES 上报告查询总 token 平均下降 38%。该结果对应带原句证据的导航树。论文另测的合成文章 Wiki 是不同实验条件。因此，当前待验差异收窄到固定候选下，按实体、关系角色和适用条件联合核验多跳原句，能否相对于低成本原文选证和已有预编译证据方法降低在线总输入并维持质量。[Ming 等](https://arxiv.org/html/2605.25480v2) · [WiCER](https://arxiv.org/abs/2605.07068) · [Yu 等 §8](https://arxiv.org/html/2610.41172v1#S8)

**主问题。** 在检索候选与阅读器固定时，能否用有限的阅读 token 保住一整条可回查原文、且各步指向正确对象并符合题目适用条件的证据链？相同语义排名用于内部消融。主要比较是在相同阅读预算下，新方法能否比标题实体桥接和公开的图选证方法保住更多有效证据链，并维持答案质量。

**待验证的核心方法。** 离线由 LLM-Wiki 记录事实对应的原句、识别对象所需的出处和原文明确的适用条件，例如地区、型号或版本。在线先核对前后两步是否连接到同一中间对象、关系方向是否正确、各步是否满足题目所需的适用范围，再将必要原句及限定条件一起选入阅读预算。保留未经验证的来源与证据缺口记录，以相同基线作为回退。检验按整条证据链装配的增量，以及离线关系记录对这一增量的独立作用。这里的文档来源版本用于追踪和失效，文中声明的产品适用版本用于判断证据能否相接。

**系统位置与直接对照，2026-11-11。** 在线模块位于候选获取之后、阅读器之前。PAGE-RAG 已在同一位置构建逐题带出处证据图并选择支持路径，SpectRAG 已使用预建图按 token 预算选证。本项目需要用对照和消融说明，实体和适用条件核验与成组保留原句分别带来多少增量。SSC 已按请求检查证据的来源时效和充分性，复用实验需明确普通缓存和带校验的证据复用已能做到什么。[PAGE-RAG](https://arxiv.org/html/2608.29753) · [SpectRAG](https://arxiv.org/html/2610.36991v4) · [SSC](https://www.amazon.science/publications/safe-and-sufficient-caching-per-request-validated-evidence-reuse-for-production-retrieval-augmented-generation)

**次问题。** 两道题共享中间事实且来源版本一致时，物化证据视图能否在第二问中省掉一次实际重排、原文访问或其他可计量处理？收益须来自视图相对于同一选证器无视图的增量，并在计入构建、更新和回退后成立。

**载体。** LLM-Wiki 的实验接口包含两阶段。离线将候选原文编译成带有主体、关系、客体、原句 ID 和来源版本的关系记录，并校验原文支持。在线在相同候选池内重排原句，只有当前题有相应关系需求、已选证据确实缺一步时，才用编译关系定位原句、检查预算并替换。SQLite 负责原型的关系、原句、版本和证据视图记录。当前比较从固定候选开始，结论适用于选证与装配阶段。全库检索、Wiki 页面生命周期、Agent 自由调用和数据库引擎比较留给独立的系统实验。

**研究贡献的最低证据。** 7 道开发题在 512 token 档中，旧 Wiki、普通实体桥接、人工提供准确出处分别保住 3、4、5 条完整链。这个小样本支持继续查找编译和装配的缺口。论文主张须由冻结后的自然样本提供同预算净增益，公开强基线提供竞争性参照，消融验证关键机制，外部样本检验适用边界。若便宜的实体桥接已达到相同效果，应按实际证据缩小贡献范围。[人工出处诊断](../topic2/reports/等预算人工出处诊断与Wiki编译说明_2026-11-11.md) · [外部对照及其边界](../topic2/reports/同预算外部压缩对照与研究脉络.md)

在已用于开发的数据集上冻结剩余子集，只能支持该数据分布内的新题泛化。严格的跨数据集实验须另外选择未参与规则和提示设计的数据来源，先核对任务、候选和预算是否可比，再锁定适配与取样。方法冻结后在该来源直接评测，保留未支持关系和不触发样本。两个已反复参与设计的数据集之间的对照不足以证明零调参迁移。外部数据尚未锁定，当前没有跨数据集泛化结果。

人工参考标注可用于开发诊断和事后证据评分。正式评测的必要原句标注由评测流程保管，并按预先统一标准判断替代支持集合。线上编译、重排、触发和装配只读预先允许的输入。固定规则下对评测语料做源文本编译是允许的语料准备，其过程与看评测题选择关系或调整规则分开记录。编译器、重排器与在线装配器的输入权限需在正式实验前核验。

保留两个已开发数据集的结果与适用范围说明。下一轮正式数据依据上节协议确定，分别检验分布内新题、实体或题型变化、外部数据来源。1,024 证据 token 为主档，512 档检验预算压力。四组共享候选、阅读器、答题提示、渲染与评测口径。三组压缩共享语义排名及冻结 tokenizer。按题族配对报告差值与区间，相同证据可共享真实阅读响应以隔离生成波动。用量和计时另按实际请求测量。

完整自然样本的结果为主表，包含未触发、原本已具备充分证据、方法失败和回退的题。关系类型子集和人工富集案例作为机制分析。整体指标与触发覆盖率一起给出，不能用富集子集的改善推算自然任务的总收益。正式实验前锁定主比较和其他消融的解释口径，保留服务失败及各组共同样本的分母。

- **证据。** 主要指标为完整必要证据链保留率。预先标注存在替代支持的题，任一充分证据集合完整即可。统计新增正确原句、挤出的必要原句、误连、真实输入变化数和回退原因。MuSiQue 段落触达另列为覆盖指标。
- **机制。** 固定候选与编译记录，比较独立选句、按链装配、按链装配但关闭实体与适用条件核验。固定装配策略再关闭 Wiki 关系，测离线记录的独立增量。统计候选可见、编译有准确出处、最终完整保留三阶段分母。在同名实体或版本干扰对照中另报告误连率与核验误拒率。受控干扰结果和自然样本效果分别呈现。
- **回答。** 报告官方 EM、F1 和配对区间。相对 A 沿用 −5 个 F1 百分点作为主档非劣验收参考，判定看预先约定区间下界。同时分别与纯重排和规则比较，区分证据改善但回答未变、答案变对但出处链仍断。必要时做目标句与等长普通句互换、移除前件和重跑原输入，识别具体案例的因果作用。
- **推进门槛。** Wiki 组在独立题上应有真实触发，较规则净增完整证据链，且答案质量未显示超过容忍线的退化。正式写作中分别给出自然覆盖率和触发子集效果。若同预算增量仍集中在零星开发案例，保留结论与案例，复核关系范围后再决定是否扩大。

## 5. 数据库支线何时继续

达到两个前置条件再扩大复用实验。首先，相关新题确有共享的原文中间事实，并有不同的下游所问属性。其次，视图能让同一本地选证器多找到可安全装配的证据，或实际省下一段可测量的工作。视图命中但输入和操作均相同的题单独计数。

| 负载 | 对照与测量 |
| --- | --- |
| 完全相同的重复题 | 比较精确缓存和视图，统一缓存命中定义 |
| 共享中间事实、答案不同的相关新题 | 对比同一选证器有无视图、完整在线重算与 A，区分共享前件对出处链和答案的作用 |
| 低复用或无关新题 | 测误触发、证据损失、回退频率与额外时延 |
| 来源改变 | 检查版本失效、重建和旧证据误复用 |

按冷启动与预热分别记录重排次数、重排 token、阅读输入和输出、回退费用、端到端 P50/P95，以及离线编译、视图构建、维护和存储开销。端到端比较使用一致的请求顺序、并发及缓存设置。只有跨新题的可用覆盖、回答质量与净收益同时成立，才将查询加速写成论文贡献。若收益主要来自精确重复，或视图与无视图证据持续相同，保留复用边界与负结果，把篇幅和实验资源集中到依赖保持。

## 6. 交付顺序

1. 复用数据暴露清单，在开发题拆分出处覆盖、条件核验和按链装配的效果，落实独立评测的数据来源。
2. 冻结方法、指标和自然抽样协议，在独立样本上开展同预算对照、机制消融与公开强基线比较，交付完整样本结果、触发覆盖、案例和配对汇总。
3. 检验外部来源与有明确适用范围的场景，按独立增量及泛化边界决定主张范围。若具备可复用机会，另做视图净收益验证。
4. 根据独立验证结果定论文贡献与最终题名，保留所有运行配置、用量、失败记录和核验日志。[会话转接记录](../会话转接_选题二.md)
