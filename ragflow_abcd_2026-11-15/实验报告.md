# RAGFlow 原生 Wiki 与原句关系 A/B/C/D 对照

2026-11-15（北京时间）。HotpotQA distractor 和 MuSiQue-Ans 官方 dev 各 50 道，均为既有开发样本。四组重新调用阿里云百炼 `qwen3.5-plus-2026-04-20`，同题同输入共用本轮响应。共完成 400 条评分，与两个数据集官方评分入口逐组核对。

## 实验定义与实现

采用 RAGFlow v1.0.0 最终索引的真实检索快照。原 RAGFlow 实例处于停止状态，这次复用已落盘的检索结果，四组均重新作答。B、C、D 每题共享完全相同、有序的检索块 ID，A 使用原快照中关闭 Wiki 的原文检索。A、B 按检索顺序直接装入全部归档块，取消此前的 2,560 装包上限。C、D 用同一版原文关系定位器及相同的可访问文档范围。两组都可以在已返回原文块里定位原句，也都可以沿返回 Wiki 块的来源 ID 读取该题候选中的对应原文。

在新目录实现 D 的离线集成。将此前从原文离线编译的事实通过文档 ID、版本和逐字原句校验，再关联到这批检索命中的原生 Wiki 块 ID，输出可复用的出处索引。记录是该 Wiki 块**来源文档中的事实**，仅此绑定并不意味着 Wiki 正文逐字包含或独立支持该事实。索引可作为实验适配层供在线选证读取，原 RAGFlow 服务与数据库没有写入。D 允许用经校验的编译关系辅助定位，C 使用同样的代码但关闭这一来源。没有按题号添加规则，也没有让官方支持标签参与装包。

短证据**无固定 token 上限**。找到唯一可核验且材料比 B 少的证据链，直接将相关原句交给阅读器；否则直接沿用 B。最长的 A/B 证据文本为 3,460 个分词器 token。每个通道的逻辑阅读次数均为 100，在线没有额外的关系定位或判定模型调用。

## 复现

代码、依赖副本、冻结题目、原文、已有离线编译、检索快照和本次产物全部保存在此目录。使用 Python 3.11.7，分词器 revision 见配置。实际百炼 159 次成功请求，4 次 HTTP 429 后重试成功，返回 281,056 输入与 816 输出 token。代码与关键输入的哈希在配置中。旧工作区文件保持原样。

```powershell
$env:PYTHONPATH = (Resolve-Path runtime).Path
python -m py_compile run_abcd.py
python run_abcd.py prepare
python -u run_abcd.py run
```

结果目录包括 `config.json`、`requests.jsonl`、`wiki-evidence-index.jsonl`、`scored.jsonl` 和 `summary.json`。正式结论仍需独立自然题。本轮优先做的是同一份检索结果下的组件增量验证。
